# Install PenEcho for the current host

The user can attach this package or supply its download link and paste this instruction (replace “attached package” with the link when needed):

> Please install PenEcho from the attached package for the app I am using, complete the supported setup, and verify that its Canvas tools work. After installation, use PenEcho when I ask to show or edit something on a canvas. Involve me only when the app requires a native confirmation or authorization.

## Agent entrypoint

Read `skills/penecho-canvas/SKILL.md` and identify the actual host from task context. A CLI available inside Claude Chat/Cowork is not evidence of a persistent local desktop host. Installation authorizes this Skill and production connection only. Preserve unrelated Skill settings, MCP entries and credentials, including local PenEcho, Dashboard MCP and UAT.

- **Local Codex / Codex Desktop / Claude Code:** Prefer the host's actual persistent plugin install capability when available. Reuse an installed complete plugin and verified connection. Otherwise run `node scripts/install.mjs --host codex --surface local` or `node scripts/install.mjs --host claude --surface local` yourself from `skills/penecho-canvas/`. The installer installs the complete Skill into its persistent user root and configures native HTTP through the host CLI. It supports repeated installation, existing supported roots and Windows official CLI launchers. `--plugin-dir` is a development loader, not persistent installation.
- **Claude Chat / Cowork account:** Prefer the native account plugin upload/install capability or install card only when the actual host exposes it. `penecho-cloud.plugin` is byte-equivalent to `penecho-cloud-plugin.zip`, supplied as a native upload artifact. If only the full plugin ZIP was attached or linked, copy its unchanged bytes to `penecho-cloud.plugin` in the working/output area and present that file through the host's actual artifact/file-delivery capability; the user need not fetch a second package. The original ZIP can be used if the native upload accepts it. Never relabel the standalone Skill ZIP as a full plugin. The filename alone does not prove an install card exists, install-card behavior has not been tested, and connector authorization remains separate. If automation is unavailable, identify the host's actual Upload/Install step. A connector's Add/Connect action and OAuth may require user interaction. A local filesystem copy or `claude plugin install` in Cowork cannot install a claude.ai account plugin. If no supported account plugin action exists, state that blocker and use only an actually supported connector path with `https://penecho.ai/mcp`.
- **Other hosts:** Use their supported plugin/connector installation. Native `mcp.json` and `.mcp.json` remain standard HTTPS configurations. The separate Hermes archive is a compatibility variant, not the Codex/Claude package.

For Codex, use actual `skills/list` with `forceReload: true` and enable only the installed disabled Skill via `skills/config/write` with its exact discovered absolute path and `enabled: true`. The helper makes these bounded native calls when available. Unavailable discovery or a rejected enable remains `unverified` or `enable-required`; do not rewrite broad TOML sections or enable unrelated entries. Claude Code activation must likewise use its actual discovery/reload capability.

Continue through supported native trust and OAuth. Reuse a consent page already opened by the host; use one opener only. Let the host store/refresh credentials. Do not request raw tokens, copy cookies, or treat configuration as authentication. Preserve a saved connection when OAuth is pending and resume login rather than adding it again.

Finish by using the host's supported reload/reconnect, checking enabled Skill discovery and actual current-task tools, and making one authenticated read-only profile or Canvas-list call with its live schema. A standalone app-server scan verifies persisted Skill state, not current Desktop tool availability. State any concrete pending step instead of promising readiness on the next turn. Installation does not request opening a Canvas. Follow the Skill's retained-session and single-opener guidance for later demonstrations.

The repository marketplace catalogs are local release material. A remote marketplace command becomes usable only after the root catalog is published; this package does not establish publication. Persistent local Claude Code plugin installation is supported through its native marketplace install command; direct complete-Skill plus native HTTP installation is the fallback above.
