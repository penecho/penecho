# PenEcho Architecture

## Overview

PenEcho is a Node.js application with a static browser client, one server-side image encoding dependency, and selectable API, Codex CLI, or Claude CLI model execution.

```text
Browser canvas
  -> sparse confirmed tiles + persistent animation scenes
  -> cropped visual request atlas with one fixed animation frame
  -> Node.js validation and model executor
  -> structured AI commands
  -> editable client-side draft layer
  -> confirmed sparse tiles or declarative animation objects
```

## Client

`public/app.js` owns the interactive runtime:

- A `20,000 x 20,000` logical coordinate system
- Sparse `512 x 512` tile allocation for confirmed content
- Pointer input, pressure-sensitive ink, erasing, pan, and zoom
- Undo/redo records for modified tiles and serialized animation scenes
- AI capture atlas generation and focus insets
- Command validation and rendering for text, formulas, plots, unified mixed drawings, declarative animation scenes, and erasure
- MathJax 3.2.2 LaTeX-to-SVG formula rendering from an explicitly allowed jsDelivr script, with local configuration and text fallback
- A fixed-screen text editor tool with movable/resizable dialogs, automatic best-effort Markdown and likely-LaTeX parsing on confirmation, an optional high-DPR Preview mode, keyboard confirmation, sparse-tile commits, and bounded sharp overlay caching
- Unconfirmed draft interactions and batch confirmation
- New-canvas workflow with overwrite, save-as-new, and discard choices backed by local snapshots
- Client-side lossless PNG export cropped to confirmed content with one tile of surrounding paper margin and adaptive 1×–2× resolution that never downscales below native size
- Persisted Manual/Auto AI mode with a temporary 0–10 second delay control, plus a fixed-width clickable per-request reasoning menu
- A registry-driven Plugins menu. Each plugin declares its stable ID, localized copy, default state, optional model-request field, and enable/disable hook; all plugin states are persisted together under `penecho-plugins`. Animation scenes are the first plugin and default to enabled, while an explicitly saved disabled choice remains disabled.
- Freehand-lasso sparse-tile ink selection with local move, proportional resize, recolor, accept, cancel, undo, and redo behavior
- English-first UI state with Chinese copy isolated in `public/locales/zh.js`
- IndexedDB snapshot storage for tile PNGs plus validated animation scene JSON and playback state

The full logical canvas is never allocated as one bitmap. Rendering composites only visible sparse tiles into the viewport canvas.

Confirmed animations never enter the tile bitmap path. `public/animation.js` normalizes data-only `animate_scene` commands and renders them with the application-owned Canvas2D renderer. Scene-level backgrounds are discarded and never serialized or painted, so the canvas paper and existing content remain visible; the model prompt also forbids backdrop fields and full-scene background shapes. `public/app.js` keeps those scenes in a persistent object layer backed by a transparent viewport-sized canvas. Animation frames clear and redraw only merged dirty screen rectangles covering changed scenes, while resize performs a full redraw. A separate interaction canvas above it contains pen previews, lasso/selection UI, animation selection handles, and unconfirmed AI drafts so opaque animation content cannot cover transient controls. The runtime starts `requestAnimationFrame` only for visible playing scenes, caps ordinary rendering at 60 FPS, drops to 30 FPS when more than 24 objects must be redrawn, and stops frames while the document is hidden. At most 20 scenes are retained, and each scene accepts no more than 32 objects and 32 motions. AI-provided JavaScript is never executed.

The animation plugin is enabled by default, and the browser persists an explicit user choice to disable it. While disabled, saved animation JSON remains available for a later re-enable, but animations do not render, participate in request atlases, affect snapshot previews or PNG exports, accept pointer input, or appear as accepted AI commands. The browser omits the plugin request field, the server omits the animation system-prompt block, and both server and client filter `animate_scene` output. Enabling it adds the bounded animation protocol paragraph, approximately 500–600 input tokens per model request. A stable feature-tour step highlights the generic Plugins entry and explains the default state, request cost, and disabled behavior to both new and returning users. With the plugin enabled, primary mouse and pen hits select the animation immediately before text, ink, eraser, lasso, or pan handling; touch requires a one-second stationary hold so ordinary canvas panning does not activate it accidentally. AI animation drafts start playing immediately and expose playback controls alongside their accept, cancel, move, and resize controls. Confirmed scenes reuse the same edit affordances when selected. About ten seconds after the latest selection or control action, the entire animation edit chrome is removed together, including its toolbar, outline, action buttons, and resize handles; clicking with a mouse or pen, or holding with touch, reveals it again. Confirmed-scene controls also close immediately after an outside click, canvas navigation, tool switch, or pen stroke.

The selection tool closes the user's freehand lasso path and clips only pixels inside that path into tile-sized fragments rather than allocating a bitmap for its whole bounding box. Pixels outside the path remain untouched even when they share the same tile or bounding box. The source pixels remain recoverable until cancel or commit; a commit records source and destination tiles as one undo step. Selection capture, movement, scaling, recoloring, confirmation, and cancellation invalidate stale recognition but never schedule or send an AI request. The text tool follows the same local-tool boundary: each editor is a DOM overlay positioned from logical canvas coordinates, keeps fixed screen-space dimensions during pan/zoom, and is removed permanently when confirmed or cancelled. Explicit input lines are preserved. Confirmation always parses a small safe Markdown subset plus delimited or conservative bare TeX such as `\pi`, `\vec{v}`, `\sum_{i=1}^{n}`, `\sin(x)`, and `A_x^2`; the Preview button only shows or hides that same final rendering. Formula segments render through MathJax, and unsupported syntax remains literal. Confirmed text records the unmodified typed source as request metadata so model transcription can use it authoritatively. Automatic requests remain exclusive to completed pen strokes and confirmed text edits, while the AI action menu remains the explicit manual request path.

## AI Request Flow

1. User input updates a dirty logical bounding box and hotspot trail.
2. After the configured post-stroke delay, the client cancels any older request and builds a white-background image around the latest user ink. Navigation and interface actions do not trigger this timer.
3. The request includes global geometry, an authoritative latest-input rectangle, an `8 x 8` hotspot grid, an optional magnified focus inset, an optional per-request reasoning selection, and only the request fields declared by enabled plugins.
4. `server.js` validates all geometry, image bounds, action/trigger pairing, reasoning selection, plugin booleans, theme/persona mapping, and payload limits. A missing reasoning field is the toolbar's explicit `Configured` mode: the server keeps the saved connection effort. The connection editor is intentionally different and never offers `Provider default`: every new or legacy-empty connection starts at the explicit PenEcho `medium` level. Missing plugin fields mean disabled. Local CLI modes first require an accepted Host, exact browser Origin, process-lifetime session cookie, and JSON content type; API mode preserves the original unrestricted HTTP request behavior. Accepted metadata is projected into fixed canonical shapes before model input, logging, or debug-artifact persistence.
5. The server resolves the PenEcho level through `src/providers/reasoning-effort.js` immediately before dispatch. Request traces retain both the requested PenEcho level and the native provider value, so connection tests and real requests can be checked against the same mapping.
6. Canvas clients request `application/x-ndjson` and show factual request phases only in the top status indicator: local canvas packing, request submission, server receipt, image preparation, model connection/wait, response receipt, validation, and an explicit retry attempt when applicable. API execution uses a separate upstream stream: PenEcho sends `stream:true` for OpenAI-compatible Chat Completions and Anthropic-compatible Messages requests, parses their standard SSE events incrementally, ignores reasoning/thinking deltas while retaining their connection activity, and assembles only the final answer text for command validation. `Waiting` ends as soon as the upstream response headers arrive; `Receiving` remains visible while SSE data is arriving, so a long generation no longer appears idle until a sudden result. Providers that ignore `stream:true` and return a normal JSON envelope remain compatible, but an SSE connection that closes without its protocol completion event is rejected as incomplete. Timely upstream headers and flushed SSE events also keep ordinary read-timeout proxies from treating a long model generation as an idle origin; merely buffering SSE at a gateway does not provide this protection. While the request is active, the top-right magic orb becomes a fixed-position Stop button. Activating it aborts the current browser's NDJSON response, which propagates cancellation through PenEcho to the upstream SSE/fetch and never cancels another client connected to the same host. The same browser POST carries progress and the terminal result, so neither progress nor cancellation adds polling, timer delay, a second HTTP request, or an additional model call. Legacy and non-Canvas callers that do not request NDJSON continue receiving one JSON response. Every downstream writer, upstream reader, attempt counter, and `requestId` is scoped to its own HTTP request, while the browser accepts events only for its current local request, so clients sharing one PenEcho host or connection cannot overwrite or observe one another's progress.
7. The server filters commands belonging to disabled plugins. The client validates commands again and displays them in an unconfirmed draft layer; enabled `animate_scene` output is normalized into bounded declarative data before preview.
8. Confirmation writes static results into sparse tiles or adds animation JSON to the persistent animation object layer. Rejection removes the draft without modifying confirmed content; continued handwriting leaves existing AI drafts visible and only appends later results to the draft batch.

Widget Refine uses a diff transport with the same editable widget capability as a complete widget response. The model receives a canonical virtual-file representation of the current widget and returns exactly one `widget_patch` command containing a standard unified diff.

Canonical source classification is part of the protocol and must follow this order:

| Stored widget | Classification | Refine virtual files | Copy source binding |
| --- | --- | --- | --- |
| `widgetType === "diagram_source"` | Locally rendered professional diagram | `widget.json`, `widget.source` | `sourceFile: "widget.source"` |
| Non-image `html_widget` with no `copyText`, explicit `sourceMirrorsHtml:true`, or `copyText` equivalent to `html` | HTML is the reusable source | `widget.json`, `widget.html`, empty `widget.source` | `copyTextFile: null` or `"widget.html"` |
| `html_widget` with non-empty `copyText` genuinely different from `html` | Direct HTML renderer plus independent professional source | `widget.json`, `widget.html`, `widget.source` | `copyTextFile: "widget.source"` |

`widget.json` is the complete editable manifest for fields that a full widget response could change: title, refresh interval, diagram kind, source format, framework version, copy label, and the copy-source binding. It also carries `tool`, `pluginId`, and the fixed `htmlFile` or `sourceFile` identity reference, which strict validation requires to remain unchanged. Host-owned id, geometry, content dimensions, revision, and runtime state never enter the editable manifest. Every HTML Refine lists an empty `widget.source` when no distinct source currently exists, so a model can add one with a standard zero-line insertion and update `copyTextFile`; changing the binding to null or `widget.html` removes or aliases the copy source without a create/delete diff. New widget creation still omits `copyText` and `copyLabel` when HTML itself is the reusable source. Content comparison is only the compatibility fallback for old saved canvases and clients: `copyText` and `html` are equivalent when they match after CRLF-to-LF normalization and trimming outer whitespace. It is deliberately not a semantic or rendered-DOM comparison. A claimed `sourceMirrorsHtml:true` is rejected when the request also contains a non-empty source that fails this exact normalized comparison. Image-search widgets have no Copy source. Related manifest, HTML, and distinct-source edits are applied atomically.

Widget creation must not minify HTML. Model guidance requires stable multiline output with major HTML elements, CSS declarations, and JavaScript statements on separate lines, ordinary lines preferably below 160 characters, and no unsafe hard-wrapping of literals. Refine preserves that formatting and must not reformat unrelated lines. When a legacy or externally supplied region is a single long/minified line, Refine must not copy that style into its replacement: it expands the lines that the requested edit necessarily replaces while leaving unrelated regions alone. The original long line can still appear as the required deletion/context side of a standard exact diff. This formatting is part of the Widget Refine protocol because unified diffs operate on complete lines: it keeps local edits small and makes exact hunk positions reliable.

Ordinary model inputs remain one JSON document but serialize stable language, theme, plugin, rendering, and canvas policy fields before the current action and geometry. Refine uses a specialized presentation with the same prefix-caching rule: stable target and policy metadata come first; every entry in `widgetEdit.patchFiles` follows as a real multiline PenEcho virtual-file block; current action, geometry, handwriting, and image metadata come after the files; retry guidance remains last. This prevents per-request coordinates from breaking the reusable prefix before plugin contracts and current widget files. It never includes an earlier response or model reasoning, and it adds no cache-specific provider parameter, extra request, filesystem operation, or model call. Before a non-empty content file becomes the patch baseline, PenEcho adds one LF only when it has no existing LF, CRLF, or CR terminator; empty files and already terminated files are unchanged. The prompt, strict patch validation, and patch application all use this same normalized baseline. PenEcho separately records whether the original file ended in a newline and, after applying a successful patch, removes exactly one normalization terminator from a file whose original lacked one. The synthetic diff aid therefore never leaks into saved HTML or professional source. Each block identifies its path, UTF-8 byte count, logical line count, patch-baseline newline state, original newline state, and a deterministic SHA-256 boundary that has been verified absent from that file. Apart from the conditional patch-only LF, the bytes between the framing delimiters reproduce the canonical file exactly: they are not JSON-escaped, minified, or prefixed with line numbers. Delimiter-adjacent line feeds are framing rather than file content. This same formatter feeds API, Codex CLI, Claude CLI, Kimi CLI, and request traces.

The server parses and applies patches with jsdiff, accepts no Git metadata or unrecognized path, requires exact old lines and context with zero fuzz, and treats multi-file edits as one transaction. Models sometimes miscount the redundant `oldLines`/`newLines` fields, offset a hunk's line number after earlier edits, abbreviate a hunk header as bare `@@`, or mistake unified diff's context marker for the first source-indent space. PenEcho recalculates the counts and reconstructs missing bare-header coordinates from the prefixed body only when the complete old-line sequence has exactly one ordered match after the preceding hunk; it applies the same unique-match rule when relocating an offset hunk. If exact matching fails, it makes one bounded indentation-repair attempt in which each context or removed line may independently be missing exactly one leading ASCII space and the complete repaired sequence must still have one unique ordered match. Added lines are never rewritten. Two or more missing spaces, tabs, trailing-space differences, changed content, or multiple compatible locations remain invalid. A bare insertion-only hunk has no old sequence from which to infer a position and is rejected. Standard zero-line insertion ranges such as `@@ -0,0 +1 @@` and `@@ -1,0 +2 @@` retain unified diff's serialized coordinate convention when checked against jsdiff's normalized internal positions. Duplicate matches, missing context, overlapping or reordered hunks, wrong paths, malformed prefixes, and extra envelope content are rejected. It validates `widget.json`, requires the original tool, plugin and fixed content-file identity references, reconstructs the ordinary complete `diagram_source` or `html_widget` command from the patched manifest and content, and runs the same plugin, supported-format, geometry, size and metadata validators used for a complete model response. A diagram may change to another supported source format when its source and manifest remain consistent. The browser never parses a model patch: it receives the validated complete replacement and immediately confirms it as one atomic widget-history entry, so leaving Hand or changing tools cannot discard a successful Refine result. Undo restores the pre-Refine widget. If the user subsequently deletes the refined widget, deletion is a separate history entry: the first Undo restores the refined widget and the second Undo restores the pre-Refine widget. If validation still fails after one model retry, the server returns an explicit model-patch error instead of a successful response with no displayable commands. Patches are transient request data and are never stored in canvas snapshots.

Refine discovery has two deliberately separate paths. New ink or a confirmed native text box that overlaps a widget or lies within 24 screen pixels creates a persistent `nearby-dirty` candidate, keeps its Refine control visible in Pen, and pauses Auto AI. When unconsumed dirty input intersects the current viewport, pointing at a widget in Pen creates a transient `viewport-dirty` candidate; it remains for five seconds after the pointer leaves and never pauses Auto AI. Both paths are determined in the parent canvas from its existing pointer position and widget rectangles: no iframe hover message or overlay is used. Explanatory copy is initially shown for ten seconds, hides when the user starts new input, and remains visible while the widget or its Refine control is hovered. Hand selection exposes only move, copy and delete controls; the underlying Refine state is retained so switching between Pen and Hand never cancels an in-flight Refine request. Switching to another tool retains the existing cancellation behavior.

Touching a widget in the parent canvas or through the existing widget touch bridge also creates the same parent-owned Refine candidate. Refine is intentionally a two-step action: the first click shows a confirmation row, outlines the widget and (when present) the viewport dirty rectangle with a fine blue dashed line, and connects the two regions. Confirming delegates to the existing `requestWidgetRefinement` path; cancelling only dismisses the row and preserves dirty input. When no dirty input is available, the candidate is muted gray and uses `implicit-polish`; the confirmation explicitly warns that a concrete instruction is preferable before the user chooses to continue.

Every AI request that builds a viewport atlas first fixes its final `sourceRect`, then asks only the live widgets intersecting that attachment rectangle for their current pixels. AI, Canvas save, and PNG export share this same snapshot-preparation entry point. PNG export alone may request the adaptive 1×–2× output scale so widget pixels match the enlarged download when the bounded widget renderer permits it; AI and snapshot persistence retain their existing 1× capture behavior. A snapshot parses the already rendered `document.documentElement` directly; it never refreshes widget data, calls the public-fetch proxy, waits for `load`, waits for a `penecho-widget-updated` event, or pauses and restarts the live widget runtime. The direct renderer's synchronous style probes are restored in the same browser task before paint, so capture cannot leave map tiles or other transform-positioned content blank or displaced. The trusted renderer and capture bridge are inserted before widget-authored scripts, so a slow or stuck third-party script cannot prevent the bridge from becoming available. Snapshotting also has no iframe hover, pointer, drag, wheel, or activation dependency.

Widgets are never captured on a timer or merely because they loaded or reported an update. AI, save, and export capture the required widgets on demand in parallel and share an in-flight capture per widget. AI waits at most three seconds for the group before continuing with the last successful in-memory image; save and export wait for the bounded capture attempt so their output is as current as possible. Every successful on-demand capture becomes the fallback for a later failed attempt. Missing or failed widget images degrade only the attachment or export rendering: they never discard dirty input, prevent `/api/ai/command` from being sent, or permanently block Canvas persistence. If the normal viewport atlas itself cannot be composed, AI sends a valid minimal image fallback so screenshot failure cannot become an AI-availability failure. Snapshot preparation is browser-local; Stop and Refine cancellation can invalidate the local preparation before any AI network request exists, stale capture completion cannot overwrite a newer request's status, and no client connected to the same host can affect another client's state.

Professional visualization uses source-first routing. When the enabled Professional Diagrams contract declares a built-in PenEcho renderer (`mermaid`, `dot`, `bpmn-xml`, `vega-lite`, `geojson`, `smiles`, or `cytoscape-json`), the model returns only `diagram_source` and PenEcho creates the display locally. A professional format without a local renderer uses `html_widget` for a faithful human-readable domain view and carries the complete editable source in `copyText`. Raw JSON, XML, YAML, DSL, or code is never the primary widget view unless the user explicitly asks to inspect raw source. General HTML remains for non-professional custom visuals and does not replace a supported source renderer. For `html_widget`, the host injects plugin CSS before the widget's own styles so the plugin remains a default framework and generated or refined widget CSS can override it normally; the final bridge stylesheet is limited to sandbox interaction and transparent outer-document constraints.

Text editors are intentionally persistent until the user chooses the check or close action. `Ctrl/Cmd + Enter` confirms the focused editor, `Escape` cancels it, and a viewport hint is shown while any editor is open. The Preview button never changes the source or confirmation behavior; it only toggles a high-DPR view of the same automatic mixed-text rendering. Confirming records exact text and geometry in `typedInput`, marks that text region dirty, and schedules Auto AI using the configured delay, but it never adds a point to `hotspotGrid`, which is reserved for actual pen trajectories. Deleting an existing text box records canvas history only: deletion is not a new model instruction and therefore does not expand dirty attention or create a hotspot. Confirming or cancelling records a half-second canvas input guard. AI draft accept/reject controls retain their separate one-second guard to prevent an extra pointer tap from becoming a new stroke.

For responses containing multiple commands, a dashed union outline and four-way handle move all remaining items together while preserving their relative positions and keeping the group inside the logical canvas. Each draft item also has independent accept and discard controls in addition to move and resize controls. An individually accepted item is written immediately and creates its own undo record; discarding the remaining drafts never removes items that were already accepted. The toolbar-level actions still accept or discard all currently unconfirmed items.

API credentials are loaded only by the Node.js process. They are never serialized into client responses or static files. Both local CLI adapters use restricted child environments that omit PenEcho API credentials.

The top-right Cloud Center is separate from local Settings. It owns account sign-in, credit balance, device linking, community discovery, favorites, redemption, and Widget/Canvas publishing. `PENECHO_CLOUD_ENV=uat` selects the dedicated HTTPS UAT service at `https://internaltest.penecho.ai`; production is the default and selects `https://penecho.ai`. `PENECHO_CLOUD_ORIGIN` is the single explicit override for unusual test deployments. Cloud credentials remain in the local Node process and community artifacts pass through checksum-verifying local proxy routes. UAT Cloud credentials use a separate state directory so they cannot replace or silently reuse a production account or device link.

## Model Executors

`penecho configure` is the interactive configuration center. Its main menu separates LLM source selection from runtime settings, and every provider page saves before checking the result. Codex checks first validate version and login and use `codex debug models --bundled` to reject an unavailable explicit model before spending tokens; all providers then run the shared small-image connection check described below. Check failure never rolls back the saved values. The default store is `~/.penecho/config.env`; `--config FILE` replaces it for configuration, diagnostics, and startup. Project and package `.env` files are not loaded implicitly. A first interactive `penecho` launch opens the configuration center when no global file or explicit process configuration exists.

Connection checks in `penecho configure`, desktop setup, and the Canvas connection editor share one provider test path. After API or CLI preflight validation, the check sends one real 1 x 1 lossless WebP or PNG image request through the selected model, credentials, image transport, and explicit reasoning effort. The Canvas editor tests its current unsaved form as an ephemeral connection and never saves, activates, or adds it. Tests are capped at 30 seconds. CLI failures return provider-specific official installation and login guidance. The desktop Canvas may additionally invoke the existing verified CLI installer through its restricted Electron bridge; ordinary and LAN browsers cannot invoke host installation. The macOS/Windows application menu keeps opening the full desktop configuration center, including on first launch or when configuration is incomplete, while the Canvas top-right Settings button opens the faster in-canvas settings panel. Additional API and CLI connections are stored in `connections.json` under `PENECHO_STATE_DIR`; the desktop sets that directory to Electron's writable `app.getPath("userData")` before loading the local server, so the file lives outside the packaged application and `app.asar`. A missing file is an empty connection list and the first save creates it atomically with user-only permissions; it is runtime user data and must not be bundled into an installer.

`AI_PROVIDER=api` retains the HTTP provider path. `AI_API_FORMAT=openai` selects Chat Completions-compatible payloads, while `AI_API_FORMAT=anthropic` selects Anthropic Messages payloads. The neutral `AI_API_URL`, `AI_API_MODEL`, and `AI_API_KEY` settings work for either format; the former `OPENAI_*` names remain read-only compatibility fallbacks and are removed on the next configuration save. The browser reasoning menu offers `Configured`, `none`, `low`, `medium`, `high`, and `max`; all newly created API and CLI connections default to PenEcho `medium`, and every settings surface normalizes an omitted effort to that explicit value. `medium` is the shared PenEcho quality/speed intent, not a claim that every provider has a same-named native parameter. `Configured` preserves the selected connection's saved level, while an explicit toolbar level overrides it for that request. PenEcho maps the six UI levels according to verified provider capabilities:

| Provider/model family | Native control | PenEcho mapping notes |
| --- | --- | --- |
| Kimi K3 API, Kimi CLI, and Kimi ACP | `low`, `high`, `max` | `none/low -> low`, `medium/high -> high`, `xhigh/max -> max`; Kimi cannot disable thinking. |
| Kimi K2.x API | model-specific thinking mode | K2.7 omits a control because thinking is always on; K2.5/2.6 map `none` to `disabled` and every enabled PenEcho level to `enabled`; unknown editable Kimi model IDs omit the control rather than guessing. |
| MiniMax-M3 API | `thinking.type=adaptive/disabled` | `none -> disabled`; every enabled PenEcho level, including default `medium`, sends `adaptive`. No invented numeric strength is sent. |
| MiniMax-M2.x API | thinking always on | Every PenEcho level maps to `adaptive`; `none` cannot disable thinking. |
| Anthropic API and Claude CLI | `low`, `medium`, `high`, `xhigh`, `max`, model-dependent | `medium` is native on effort-capable models. Opus 4.5 uses `output_config.effort` without adaptive thinking and caps `xhigh/max` at `high`; Claude 4.6 maps `xhigh` to `max`; current supporting models keep `xhigh/max`. Known older API models omit unsupported enabled-effort controls. `none` requests disabled thinking. |
| Codex CLI | model-dependent effort catalog | `medium` is native. `max` stays `max` for GPT-5.6 models and maps to `xhigh` for the installed GPT-5.2/5.4/5.5 catalogs; `none` maps to `low` because Codex CLI has no disabled-thinking value. |
| Generic OpenAI-compatible API | `reasoning_effort`, endpoint-dependent | Known values pass through; GPT-5.6 keeps native `max`, while unknown or older model IDs map PenEcho `max` to the more widely compatible `xhigh`. Custom legacy configured values remain pass-through because compatible endpoints differ. |

PenEcho does not set `temperature` in API requests, connection checks, or CLI invocations, so each provider and model applies its own default. Anthropic `none` sends `thinking.type=disabled` without `output_config`. Enabled effort-capable adaptive models send `thinking.type=adaptive` plus the mapped `output_config.effort`; Opus 4.5 sends only its supported `output_config.effort`, and known older models omit unsupported effort fields. `MAX_TOKENS` controls the response allowance for API reasoning levels and plugin-authoring requests. It defaults to 20000, must be larger than 15000, and includes both thinking and visible response tokens. The shared system prompt used by every API format and local CLI instructs the model never to spend more than half of its available output-token allowance on internal reasoning and to reserve at least half for one complete final response; this is a portable soft constraint rather than a provider-specific hard token control. The base system prompt also asks the model to keep its final JSON within approximately 6144 tokens, and a true output-limit stop is reported explicitly rather than as a generic JSON parse failure. The small Anthropic Test & Save probe omits adaptive thinking but retains a supported mapped effort field; MiniMax tests send the same required thinking mode as real requests. PenEcho does not issue startup or periodic probe requests and does not switch credentials after a failure.

`AI_PROVIDER=codex-cli` routes the same model input through `codex-cli.js`. The adapter creates a unique temporary directory, writes the selected atlas as `atlas.webp` or `atlas.png`, starts the installed `codex exec --json` without shell string interpolation, and passes the prompt over stdin. It incrementally parses JSONL output, retains the final `item.completed` agent message, and returns it as soon as `turn.completed` arrives. A CLI process that remains alive after the completed turn is terminated and cleaned up in the background, so process-exit cleanup cannot delay the canvas response. `--output-last-message` remains as a compatibility fallback when a CLI exits successfully without the expected final events. Every invocation uses private temporary home, Codex home, AppData, XDG config, and cache roots and copies only the existing Codex `auth.json`. User configuration, profiles, rules, skills, memories, plugins, MCP declarations, and project instructions are excluded, while strict runtime overrides empty or disable those surfaces. `CODEX_CLI_MODEL` applies an explicit model override; otherwise Codex chooses the default for the isolated session rather than loading `model` from the user's config. The adapter applies the mapped effort through Codex's `model_reasoning_effort` configuration override. The installed `penecho` command exposes the same transient overrides as `--model` and `--effort`, with command-line values taking precedence over configuration. It retains an ephemeral session, a read-only sandbox as defense in depth, bounded event and stderr handling, a restricted child environment without PenEcho API keys or proxy credentials, immediate process-tree cancellation, timeout handling, and retried temporary-directory cleanup. Timeout and failure traces retain the bounded Codex event summary, stderr tail, and any generated `last-message.txt`. Local CLI execution is latest-request-wins per Canvas client: a valid new request invalidates and terminates only that client's previous request, starts without waiting for the retiring process to finish cleanup, and discards the superseded response. Requests from different connected clients run independently.

`AI_PROVIDER=claude-cli` routes the same model input through `claude-cli.js`. It starts the authenticated Claude Code CLI in print mode, supplies the fixed PenEcho system prompt, and sends one streaming JSON user message containing request metadata plus the selected base64 atlas image and matching PNG or WebP MIME type. Runtime flags disable built-in tools, explicitly deny Agent and Task, provide no custom agents, disable MCP configuration, slash commands, browser integration, prompt suggestions, and session persistence, while child-environment overrides suppress nonessential traffic and terminal-title requests. `AI_EFFORT=none` additionally sets `MAX_THINKING_TOKENS=0`, which makes Claude Code send `thinking.type=disabled`; because `none` is not accepted by the CLI effort parser, the process receives an internal `--effort low` plus a flag-level `--settings` override setting `CLAUDE_CODE_EFFORT_LEVEL=low`, preventing a user-level `max` from competing with the disabled-thinking request. Other non-empty efforts leave extended thinking enabled and are applied through both `--effort` and the same settings override, while an empty effort preserves Claude Code's native behavior. The adapter incrementally parses stream JSON, requires an empty tool and MCP initialization, aborts on any tool-use event, and returns immediately when the successful final `result` arrives; a process still alive afterward is terminated and its temporary directory is cleaned in the background. Bounded event summaries and stderr tails are retained on failures and timeouts without recording prompts. `CLAUDE_CLI_MODEL` accepts an alias or full model ID; when omitted, Claude Code chooses its configured default. The installed `penecho` command exposes the same transient overrides as `--model` and `--effort`, with command-line values taking precedence over configuration.

`PENECHO_AI_IMAGE_FORMAT` applies to API, Codex CLI, and Claude CLI. The browser's validated PNG remains the source artifact; `webp`, the default, is encoded losslessly with Sharp before dispatch, while `png` sends the source unchanged. API providers that explicitly reject WebP with HTTP 400, 415, or 422 are retried once with the original PNG. Timeouts, 5xx responses, and model-output parsing failures never trigger this transport fallback. Request traces retain both the source PNG and selected outbound artifact when they differ.

`AI_TIMEOUT_SECONDS` applies to API and CLI model attempts. It defaults to 180 seconds and accepts integer values from 10 through 600. `xhigh` and `max` attempts use twice the configured value. After the resulting total timeout is reached, a streaming response remains connected while data continues to arrive and is aborted only after 10 seconds without stream activity. `Settings` also owns the restart-applied `MAX_TOKENS` API response limit, image format, request tracing, trace retention, `HOST`, `PORT`, and the initial `AUTO_AI_DELAY_SECONDS`; request traces default to `~/.penecho/logs/requests`.

All executors listen on the configured `HOST`, which defaults to `0.0.0.0`, so localhost and LAN access work without a public-origin setting. API mode preserves the original unrestricted Host, Origin, Cookie, and content-type behavior for local, LAN, proxy, and other remote deployments. Codex and Claude CLI modes share an automatic process-launch boundary: accepted Hosts must match loopback, an actual network-interface address, the computer hostname, or its `.local` form; the client address must be local or on a directly connected network. The root document issues a process-lifetime `HttpOnly`, `SameSite=Strict` cookie scoped to `/api/ai/command`, and CLI launches require the matching canonical `Origin` and JSON content type. Static responses restrict scripts to the application itself and the jsDelivr origin used by the integrity-pinned MathJax bundle.

Codex CLI mode invokes Codex itself, and Claude CLI mode invokes Claude Code itself. Neither mode selects a local Ollama-style provider. Local or self-hosted model endpoints use `AI_PROVIDER=api` with an OpenAI-compatible URL.

## Unified Drawing Protocol

`public/draw.js` validates and renders the `draw` command independently of the main interaction runtime. A command contains one integer global `origin`, parallel `types` and `items` arrays, and optional index arrays for closure, translucent fill, and arrowheads. Primitive coordinates are integer offsets from the shared origin.

Supported item encodings are:

- `line` and `smooth`: flat point pairs `[x1,y1,x2,y2,...]`
- `rect`: top-left and size `[x,y,w,h]`
- `ellipse`: center and radii `[cx,cy,rx,ry]`
- `circle`: center and radius `[cx,cy,r]`
- `arc`: center, radii, start angle, and signed sweep `[cx,cy,rx,ry,startDeg,sweepDeg]`; angle `0` points right, positive sweeps are clockwise, and negative sweeps are counter-clockwise

The module computes one union bounding box across all primitives, smooth-curve extrema, arc extrema, stroke padding, and arrowheads. Neither the API response path nor the client rejects valid in-canvas drafts by aggregate logical area, destination-tile count, or backing-raster pixel count. Drawings and text may still downsample their backing bitmap while retaining logical dimensions so draft movement, independent width/height resizing, proportional scaling, confirmation, and sparse-tile commits preserve the intended canvas size. One mixed command therefore behaves as one draft item. Text and formula commands are allowed to overlap the drawing union so labels can remain inside diagrams.

## Local Snapshot Format

The browser uses IndexedDB database `penecho-canvas-history` with two stores:

- `snapshots`: metadata, preview blob, theme, timestamp, view transform, animation scene JSON, renderer version, transform, playhead, and paused state
- `snapshot-tiles`: one PNG blob per populated tile, indexed by snapshot ID

This keeps list rendering lightweight and avoids loading every full tile blob until a snapshot is selected. Snapshot loading invalidates active recognition state, discards unconfirmed drafts, clears undo/redo history, reconstructs confirmed tiles, validates animation JSON again, and resumes each scene from its saved playhead without accumulating time while the application was closed.

The current loaded or saved snapshot is tracked for the lifetime of the page so the New action can overwrite it safely. Saving as new creates a distinct snapshot, while every New path cancels active recognition, removes unconfirmed drafts, clears undo/redo state, and recenters the blank canvas.

## Server

`server.js` provides:

- Static file serving from `public/`
- Configuration supplied by the `penecho` launcher without exposing values to the browser
- Selectable API, Codex CLI, and Claude CLI model execution
- Single-key API execution without background probe requests
- Strict AI request validation and canonical metadata projection
- Same-origin, cookie-bound authorization before local CLI process launches
- Structured response retries and plot fallback
- Optional localhost-only debug endpoints plus credential-redacted per-request tracing, disabled by default; request traces retain source PNG and configured outbound image artifacts, MIME types and byte sizes, exact outbound bodies, transport/semantic attempts, raw/parsed responses, format fallback state, and terminal state with a configurable rolling limit of 100 by default
- Bounded log rotation

## Rendering Dependencies

The server uses Sharp to encode validated PNG atlases as lossless WebP for every model executor when WebP is selected. It uses jsdiff 9.0.0 to parse and apply the bounded unified diffs returned by Widget Refine; PenEcho separately enforces the trusted file set and exact-position transaction rules. Formula commands use MathJax 3.2.2 from a version-pinned jsDelivr URL, protected by a SHA-384 Subresource Integrity check and anonymous CORS mode. MathJax configuration stays in `public/mathjax-config.js`, and formula rendering falls back to local text if MathJax is unavailable. Static responses allow scripts only from the application itself and the pinned CDN origin.
