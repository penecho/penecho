# Widget 最大化：单一页面滚动验收 · 2026-09-24

> Update: the entry-scale requirement is superseded by [width-fit presentation](widget-width-fit-20260924.md). Existing single-scroll and saved-height protections remain applicable.

本轮修正此前“外框与页面自身两条纵向滚动条可以共存”的错误验收标准。当前要求是：最大化只有一个外层页面滚动入口，鼠标停在内容上也能上下滚动；继续保留入场比例与保存高度下限。

## 已确认原因

1. 外框 `overflow:auto`，iframe 又以保存高度为下限，页面正文自身还可能超过 iframe：两个独立滚动范围同时存在。
2. Widget 桥接样式给内部 html/body 注入 `overscroll-behavior:contain`。内部滚动到边界后不会传给外层。因此只在外层空白处滚动有效，不能用“末尾元素可被程序滚入视口”证明滚轮可用。
3. 单纯让宿主两层尺寸一致，不能覆盖正文比页面视口长、或 body 自己滚动的情况。直接用正文高度扩大 iframe 又会重新引入 vh / 百分比高度反馈。

## 修改

- 外层保留一个原生页面滚动条。内部文档 / body 的页面滚动条不显示，滚轮、页面导航键和滚动条操作使用同一外层滚动位置。
- iframe 的布局高度仍只取决于可用窗口高度、入场比例、用户主动缩放及保存的 contentH。内容测量仅更新外层滚动占位，不改变 iframe 布局视口。
- 通过同一网格区域的滚动占位与 sticky iframe，把外层位移和内部正文位移组合成连续的页面滚动；不移动、克隆或重新挂载 iframe。
- 识别文档根滚动及完整高度 body 滚动。保留文本输入区、图内可滚动区域等真正嵌套控件的滚动；其可消费当前滚动方向时不抢事件，达到边界后交给外层。已由应用取消的滚轮事件及 Ctrl/Cmd 组合不接管。
- Observer 仅在最大化时启用、按动画帧合并、尺寸不变不回传、退出后清理。截图期间不测量临时布局；修正截图释放路径遗留的旧函数引用。
- 超宽页面支持外层横向滚动，顶部工具栏保持可见。正常页面不增加横向滚动范围。
