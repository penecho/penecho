# Widget 最大化尺寸浏览器验收

日期：2026-09-23。范围：正式 071 项目 `main` 的本地未提交修改。

## 环境与方法

- 用户明确批准后，从正式项目启动临时 PenEcho Web 实例；使用独立测试数据、回环地址和不可用的测试模型地址，没有调用模型。
- 浏览器：Codex 内置 Chromium；桌面视口 1280 × 720，窄屏视口 390 × 844。
- 检查英文、中文、100% 与产品支持的 125% 界面缩放，以及 Widget 的 80% 显示比例。
- 使用正常 Canvas 存储 API 和画布资料库载入样例。浏览器操作通过真实控件、键盘和滚动完成；尺寸检查为只读 DOM 测量。
- 原场景来自用户指定的共享画布，HTML 和原始内容尺寸 2012 × 899 保留；仅在测试副本中调整画布上的摆放尺寸。
- 通用样例保留在 `test/fixtures/widget-presentation.cjs`。通过其 `snapshot(name, {html})` 导出正常画布快照，再经 `/api/canvases` 加载，可重复验收。

## 验收发现并补修

1. 浏览器宽窄屏切换会短暂报告错误的 iframe 逻辑宽度。诊断捕获到原 900px 视口变为 3071px，宿主测量 3072px 并写回，造成文字缩小。现在父层传递实际指定的 `viewportWidth`，子层等到浏览器视口与该值一致后才测量和重新分类布局；保留一个显示像素量级的舍入容差。后续 resize/state 事件仍使用原来的测量调度器。
2. 原有最大化 CSS 直接使用 `100vw/100dvh`，在 125% 界面缩放下实际达到 1600 × 900，按钮超出 1280 × 720 屏幕。现在复用现有的界面缩放视口变量。100% 和窄屏行为保持原有计算方式。
3. 保留 Live Clay 覆盖层定位修复，以及只在连续不收敛时恢复该 Widget 原始布局和内部滚动的保护。没有恢复“扣除猜测高度”的算法。

## 最终浏览器结果

以下尺寸是 iframe 的逻辑宽高，不是缩放后的屏幕像素。

| 场景 | 实测结果 | 结论 |
| --- | --- | --- |

| Live Clay 80% 显示比例 | 2019 × 907，稳定 | 通过，少量 CSS 缩放舍入差异未继续增长 |
| Live Clay 退出并重新最大化 | 回到 2012 × 902，暂停状态保留 | 通过 |
| Live Clay 窄屏 | 2012 × 903，页面没有横向溢出 | 通过 |
| 正常长文档，桌面 | 900 × 2855 | 通过，保持自然内容高度 |
| 按钮延迟追加 600px 内容 | 900 × 3455 | 通过，真实增量完整保留 |
| 追加内容后重新最大化并切窄屏 | 900 × 3453 | 通过，没有放大到 3072px 宽 |
| 窄屏移除新增内容 | 900 × 2853，输入值保留 | 通过，恰好减少 600px |
| 连续三次宽窄屏往返 | 最终仍为 900 × 2853 | 通过 |
| 正常长文档滚动到底 | 目视看到完整末尾文字，桌面与窄屏均可达 | 通过 |
| 嵌套滚动区 | iframe 900 × 2130，普通内容区展开到约 1909px | 通过，末尾完整可见 |
| 输入框独立滚动 | textarea 约 89px 高、内容约 371px，overflow 为 auto | 通过，没有被展开成整个输入内容高度 |
| 通用 200vh 高度反馈 | 恢复为 900 × 600 | 通过，原始滚动恢复 |
| 保护后退出并重新最大化 | 仍为 900 × 600，输入值保留 | 通过，没有重启循环 |

不同显示比例下有约 1–几 px 的浏览器取整差异；判断同时检查稳定性、内容末尾可达和真实画面，没有把“停止增长”单独作为正常显示的依据。
