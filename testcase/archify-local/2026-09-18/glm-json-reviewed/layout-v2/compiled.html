PenEcho MCP 架构

外部 AI 客户端经 stdio 桥或直接 HTTPS 到达本地 Node 宿主的 MCP 接入，经 RPC/schema与会话分派调用共用画布操作，由已授权浏览器渲染 Widget；guidance 为不进浏览器的只读分支；Cloud MCP 为可选通道，详见下方说明。

外部客户端PenEcho Node 宿主浏览器持久状态

端口与部署

  • 主宿主由 src/server/main.js 创建 MCP service，主 Web 服务默认 3888
  • 多个候选端口不表示多台服务器；接入/RPC/会话/浏览器通道同属一个宿主

发现与凭据

  • discovery-client.js / lan-discovery.js 提供已认证端点发现、共享缓存与 LAN 广播
  • 先尝试已知地址和缓存，按需发现，无常驻发现守护进程
  • 主机与桥接各有信任/凭据资料，图中仅示职责

生命周期

  • HTTP 空闲清理不会终止仍打开 stdin 的轻量桥；下次调用重连并恢复原文档
  • 可能已提交的写请求不可盲目重放

日志与图片

  • 开启请求日志时 request-trace.js 记录多轮交互；日志目录与 Agent 日志平行，非画布源文件
  • /mcp/images 复用同一 HTTPS 接入，经服务端有界图片处理交到指定文档

内置 Agent

  • PenEcho 内置 Agent 的 document-tools.mjs（Node 端代码）复用共用画布操作与 guidance，有独立会话绑定
  • 不是外部 MCP 调用的必经环节

Cloud 可选通道（云端内部未展开）

  • 用户开启 Cloud MCP 后，浏览器经本地 /api/mcp/cloud-canvas 接入 Node 宿主内的 CloudMcpBridge（cloud-mcp-bridge.js）
  • Bridge 带宿主设备凭据连接 Cloud 的 WSS /api/v1/mcp/device-canvas，双向转发画布帧
  • 画布操作由 Cloud 的 MCP 运行时发起，不代表云端请求必须串过本地 HTTPS MCP 工具分派
  • remote.js 另提供可复用的远端浏览器通道适配
  • 未臆造云端数据库、队列或内部部署

虚拟文件

  • read_file / patch_file 围绕同一文档的虚拟源文件工作
  • 画布文档与快照由浏览器持有，不是 Node 文件存储
