电商服务架构（给定设计）

示例设计，非特定云厂商 · 用户 → 边缘/公网入口 → 私有应用区 → 私有数据区
网关下游服务：3（商品 / 订单 / 账户，并行调用，非串联）
Worker：2（库存、通知，需幂等消费）
同步通信：HTTPS　异步：消息队列
数据库公网入口：无
组件与关系图

A同步路径（HTTPS）

用户经 CDN 获取前端静态资源。
业务请求经 公网 LB → API Gateway 进入私有应用区。
Gateway 分别并行调用商品 / 订单 / 账户三个服务；三者之间不串联。
订单状态统一通过订单服务查询。

B异步路径（消息队列）

订单服务写入订单库后，向消息队列发布订单事件。
库存 Worker 消费订单事件 → 更新库存数据库 → 发布处理结果。
通知 Worker 消费处理结果 → 调用网络边界外的邮件供应商。
两个 Worker 均须幂等消费（重复投递不产生副作用）。

C边界与安全规则

应用区与数据区同属一个私有网络；CDN 与邮件供应商在网络之外。
数据库、缓存、消息队列位于私有数据区，无公网入口。
唯一公网入口：CDN（静态资源）与公网负载均衡器（API）。
图例：蓝 = 入口/服务 · 橙 = 应用区与处理组件 · 绿 = 数据区存储 · 紫 = 异步/边界外 · 红色虚线 = 明确不存在的关系（服务间串联）· 实线箭头 = 实际调用/数据流。
