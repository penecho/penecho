## 加载隔离与通用规则

- `visual-rules/registry.json` 只存名称、用途、作用域；正文按独立 ID 读取和缓存。
- `penecho_get_guidance({id:"architecture"})` 返回架构图正文与独立 hash。只约束当前产物中的架构区域，不形成永久会话模式。
- 普通 Visual Explorer 只有简短目录入口；原先夹在基础契约中的架构段落已移出。其他图、普通 HTML、数学与物理规则不读架构正文。
- 将来时序图、Gantt、PPT 可分别注册自己的 ID 和文件。目前未宣传未实现的规则。
- 不新增 renderer、Widget 类型、diagram JSON schema、运行时依赖或模型必填标记。
- 外部模型可以在对话中保留之前读到的工具结果。文件与加载器隔离可验证，但不能保证所有外部模型都完美遵守作用域。

R9 通用正文主要约束：先确定真实关系与边界；实体短、详情另列；节点、端口、线段、标签共享几何分配；标签完整文本框避让弯折和箭头；框线按子实体和路线留白；按语义域而非面板次序绑定颜色；同时验收实际截图中的绘制结果。构图、方向、节点数量、视图数量由模型裁量，没有固定 MCP 模板。

当前正文 5,273 UTF-8 字节，按字符/4 粗估 **1,315 tokens**，不是 GLM tokenizer 精确结果。仅匹配架构图时加载。基础指导的目录为 465 字符、约 117 个估算 tokens；工具 schema 增长约 38 个估算 tokens，没有新增工具。详见 `rule-size-comparison.json`。

## 固定实验输入与边界

`facts.md` 为提前整理的 MCP 代码事实，SHA256 为 `6ded9202415129d7f3888d65b251ac756a64ecb339c2f7335c9ef2ee738dc532`。后续轮次复用这份数据，避免将重复调查耗时混入生成测试。

`prepare-job.cjs` 通过生产 `PenEchoStdioServer` 的 initialize / tools/call 实际读取 `visual-explorer` 与 `architecture`，保存原始 guidance 返回及哈希，再发送给用户指定的 GLM-5.3-Flash API。API 本身不开放工具，模拟模型已搜集事实并读取规则后的创作阶段；Codex 将它返回的 HTML 原样交给 PenEcho MCP 并检查像素。这不是模型自主选工具的全链路评测。

必须区分实验类型：

- R1–R5、R7、R8 是相同事实、请求、基础指导与参数的独立生成，主要变动为架构规则正文。
- R5-after-facts 调整指导位置/角色，属于上下文顺序实验。
- R6、R8 的修正轮次及 R9 加入上一轮 HTML 和具体缺陷反馈；后续轮次还提供 MCP 截图。因此它们是修正流程实验，不是首次生成。
- `mcp-r9-guidance.job.json` 仅保存 R9 基础输入快照，未用作新的独立生成请求；实际执行的是 `mcp-r9-visual-repair.job.json`。

模型输出没有人工重新画图。R6、R8 geometry 的补丁 JSON 缺少外层结尾括号：失败原文保留，单独恢复运输包裹（R8 另移除 Markdown fence），只严格应用模型原始 old/new 字符串。R9 返回完整 HTML，未经过补丁重建或人工 HTML 修改。
