## 已落地的加载隔离

- `visual-rules/registry.json` 只存规则名称、用途和作用域；独立正文按 ID 读取并缓存。
- `penecho_get_guidance({id:"architecture"})` 返回架构图专属正文和独立 hash。
- 普通 Visual Explorer 不包含架构图规则正文，仅提供简短目录入口。原先混在基础契约中的架构段落已移出。
- 普通 HTML、数学和物理指导保持原文；架构规则不启用特殊 renderer，不修改 Widget 类型或既有产物。
- 未来时序图、Gantt、PPT 可各自注册独立 ID 和文件，目前没有宣传尚未实现的规则。
- 工程层的隔离不能抹除外部模型已读过的对话历史；规则明确限制到当前产物中的架构区域，不形成永久模式。

## 固定实验输入

`facts.md` 是提前整理的代码证据；`evidence-manifest.json` 保存源码版本与哈希。
每轮由生产 MCP stdio handler 真实调用基础指导和架构规则，再将原始返回与固定资料送给 GLM-5.3-Flash。
所有轮次的事实、用户请求、基础指导、模型及参数相同，只改架构规则；没有把上一轮 HTML 或特定坐标传给下一轮。
API 调用不开放工具，模拟模型已完成资料搜集与规则读取后的创作步骤。Codex 转交原始 HTML、监督实际效果；这不是自动工具选择的全链路评测。
