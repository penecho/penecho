A · 桥接与端点发现 如何找到并连上宿主

  • session-client.js：stdio 生命周期、HTTPS /mcp、TLS 校验、连接池与有界并发。
  • 桥接读共享主机凭据与发现缓存；桥接侧另有自己的信任资料（图中只画职责）。
  • discovery-client.js / lan-discovery.js：先试已知地址与缓存，再按需发现；无常驻发现守护进程。
  • 空闲清理不终止仍开着 stdin 的桥；下次调用重连并恢复原文档，不盲目重放已提交写请求。

B · 宿主职责拆分 同一 Node 宿主，不是多台服务器

  • main.js:4146 创建 MCP service，复用本地宿主与配置；端口冲突后可选空闲端口——候选端口不是多台服务器。
  • 图片上传 /mcp/images 复用同一 HTTPS 接入与认证，经有界图片处理交付到指定文档。
  • 开启请求日志后，request-trace.js 记录多轮 MCP tool/browser 交互；日志不是画布源文件。

C · 两种存储，所有者不同 不要混画成一种

  • Node 端持久绑定：conversation-bindings.js 保存 client/sessionKey → canvasId/documentId。
  • 浏览器持有画布文档与快照，不存为 Node 文件。
  • 浏览器连接 ID、文档 ID、业务 sessionId 与 HTTPS 传输 session ID 是不同标识。
  • 工具的虚拟 source path（如 objects/<id>/widget.html）不是模型电脑上的真实文件路径。

D · 浏览器运行时与 Widget 画布动作的真实执行处

  • mcp-runtime.js：opt-in WebSocket，hello / 打开文档 catalog / 收 call 回 result；处理心跳、断线与取消。
  • 浏览器关闭授权后，外部画布操作不再被接受。
  • Widget host 以沙箱 iframe 渲染外部 AI 传入的 HTML；后续 read_file / patch_file 围绕同一文档的虚拟源文件工作。
  • 内置 Agent（document-tools.mjs）也复用共用画布操作，但有自己的会话绑定——不是外部 MCP 的必经环节。

E · guidance 只读分支 不进浏览器，不调模型

  • penecho_get_guidance 由 rpc.js 分派到独立只读分支，直接从 authoring-guidance.js 返回 id / hash / document。
  • schema.js 对 guidance 输入做校验，与工具 schema 同源。
  • 本轮新增 architecture 独立规则；通用 visual-explorer 只列规则目录，不含架构规则正文。

F · 读图要点 主图与详情的对应

  • 主调用链：AI 客户端 → 桥 → HTTPS 接入 → RPC/Schema → 会话分派 → 共用操作 → 浏览器 runtime → Widget。
  • 直接 HTTPS 客户端绕过桥，进入同一接入点，不经过另一个模型服务。
  • 紫色虚线分支（guidance）与两个存储框独立于主链路。
  • 橙色虚线区为可选 Cloud 通道：云端发起、双向帧转发，云端内部未展开。
