Astdio 桥与发现桥 / 传输

  • stdio 桥 = 轻量 client.js（源码 session-client.js），不是完整 PenEcho 应用；读共享主机凭据与发现缓存，经 HTTPS /mcp 复用连接。
  • discovery-client.js / lan-discovery.js：先已知地址与缓存，再按需发现，无常驻发现守护进程。
  • HTTP 空闲清理不终止仍开 stdin 的轻量桥；下次调用重连并恢复原文档，不盲目重放可能已提交的写请求。

B宿主接入与认证Node 宿主

  • direct-http-service.js 拥有 HTTPS listener、认证与传输会话；main.js 创建 MCP service。
  • 端口：主 Web 服务默认 3888；MCP HTTPS 优先 3922 / 13922 / 23922，冲突后取空闲端口 —— 候选端口不是多台服务器。
  • 图片上传 /mcp/images 与工具调用共用同一 HTTPS 接入及认证，非独立上传服务器。
  • 开启日志时，request-trace.js 记录多轮 tool / browser 交互；日志不是画布源文件。

C会话与绑定存储绑定存储

  • service.js 持有已授权浏览器连接、打开文档目录与画布会话，并把工具调用绑定到明确浏览器与文档。
  • 持久绑定：client/sessionKey → canvasId/documentId（conversation-bindings.js），Node 侧存储。
  • 浏览器连接 ID、文档 ID、业务 sessionId、HTTPS 传输 session ID 互不相同。

D浏览器画布运行时浏览器

  • opt-in 浏览器经 WebSocket /api/mcp/canvas（mcp-runtime.js）连接；发 hello / 文档 catalog，收 call 返 result；心跳、断线、取消均有处理。
  • 浏览器关闭授权后拒绝外部画布操作。
  • canvas-documents.js 管理文档与执行上下文；文档与快照由浏览器持有，不是 Node 文件存储。
  • Widget 在沙箱 iframe 渲染；虚拟源路径（如 objects/<id>/widget.html）不是主机真实路径，read_file / patch_file 围绕同一文档虚拟源工作。

E规则分支与内置 Agent

  • 规则penecho_get_guidance 从 authoring-guidance.js 读取规则（id/hash/document），是 RPC 的独立只读分支：不进画布队列、不调模型。
  • visual-explorer 仅列规则目录；architecture 为独立规则正文，惰性加载。
  • Agent内置 Agent（document-tools.mjs）复用共用画布操作与 guidance，有独立会话绑定，不是外部 MCP 的必经环节。
Cloud 可选通道（云端内部未展开）：用户开启后，浏览器经本地 /api/mcp/cloud-canvas 接入 Node 宿主内的 CloudMcpBridge（cloud-mcp-bridge.js），它带宿主设备凭据连接 Cloud 的 WSS /api/v1/mcp/device-canvas 双向转发画布帧。该路径由 Cloud 的 MCP 运行时发起，不表示云端请求必须串过本地 HTTPS MCP 工具分派；remote.js 另提供可复用远端浏览器通道适配。Cloud 自身内部实现不在本轮调查范围。
