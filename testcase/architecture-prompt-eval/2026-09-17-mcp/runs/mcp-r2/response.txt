    <div class="card cA">
      <h2><span class="tag" style="background:#0e7c86">A</span>stdio 桥与发现</h2>
      <ul>
        <li>桥是轻量进程，<b>不是</b>完整 PenEcho 应用；分发光为 <code>client.js</code>。</li>
        <li>先试已知地址与缓存，再按需发现（<code>discovery-client / lan-discovery</code>），无常驻守护进程。</li>
        <li>桥与宿主各持自己的信任/凭据资料；图中只画职责，不写凭据内容。</li>
      </ul>
    </div>
    <div class="card cB">
      <h2><span class="tag" style="background:#1d5fb8">B</span>宿主内部职责</h2>
      <ul>
        <li>接入 / RPC / 分派 / 浏览器通道是<b>同一宿主</b>内的职责划分。</li>
        <li><code>direct-http-service.js</code>：HTTPS listener、认证、传输会话；<code>rpc.js</code>：JSON-RPC；<code>schema.js</code>：工具输入校验。</li>
        <li><code>main.js</code> 创建 MCP service，复用本地宿主；主 Web 服务默认 3888。</li>
      </ul>
    </div>
    <div class="card cC">
      <h2><span class="tag" style="background:#1c7a3d">C</span>浏览器端与 Widget 交付</h2>
      <ul>
        <li>已 opt-in 的浏览器才连 <code>/api/mcp/canvas</code>；关闭授权后不再接受外部画布操作。</li>
        <li>浏览器执行具体文档动作；Node 端<b>不是</b> HTML 排版渲染器。</li>
        <li>Widget 在沙箱 iframe 内渲染；后续 <code>read_file</code> / <code>patch_file</code> 操作同一文档的虚拟源文件。</li>
      </ul>
    </div>
    <div class="card cD">
      <h2><span class="tag" style="background:#c2570f">D</span>两种存储 · guidance 分支</h2>
      <ul>
        <li>持久绑定（Node，<code>conversation-bindings.js</code>）与文档/快照（浏览器）<b>所有者不同</b>。</li>
        <li>浏览器连接 ID、文档 ID、业务 sessionId、HTTPS 传输 sessionId 互不相同。</li>
        <li><code>get_guidance</code> 是 RPC 独立只读分支：不进浏览器画布队列，不调用模型。</li>
      </ul>
    </div>
    <div class="card cE">
      <h2><span class="tag" style="background:#8a94a0">E</span>周边通道</h2>
      <ul>
        <li>图片上传 <code>/mcp/images</code> 复用同一 HTTPS 接入与认证，服务端有界处理后交给指定文档。</li>
        <li><code>request-trace.js</code> 按需记录多轮交互；日志不是画布源文件。</li>
        <li>Cloud 通道由 Cloud MCP 运行时发起，不代表云端请求必经本地工具分派。</li>
      </ul>
    </div>
