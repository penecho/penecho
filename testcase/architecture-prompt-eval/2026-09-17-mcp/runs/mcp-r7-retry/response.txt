  <div class="panels">
    <div class="panel pa"><h3><span class="tag">A</span>接入与端口</h3>
      <ul>
        <li><code>direct-http-service.js</code> 拥有 HTTPS listener、认证与传输会话；候选端口 3922 / 13922 / 23922，冲突后可选空闲端口——仍是<b>一台服务器</b>。</li>
        <li>图片上传 <code>/mcp/images</code> 复用同一接入与认证，经有界处理交给指定文档，不是独立上传服务器。</li>
        <li>HTTP 空闲清理不会终止 stdin 仍打开的轻量桥；下次调用重连并恢复原文档，已提交写请求不盲目重放。</li>
      </ul>
    </div>
    <div class="panel pb"><h3><span class="tag">B</span>会话与绑定</h3>
      <ul>
        <li><code>conversation-bindings.js</code> 持久化 client/sessionKey → canvasId/documentId。</li>
        <li>四种 ID 互不相同：浏览器连接 ID、文档 ID、业务 sessionId、HTTPS 传输 session ID。</li>
        <li>开启请求日志时 <code>request-trace.js</code> 记录多轮 tool / browser 交互；日志不是画布源文件。</li>
      </ul>
    </div>
    <div class="panel pc"><h3><span class="tag">C</span>guidance 只读分支</h3>
      <ul>
        <li><code>penecho_get_guidance</code> 在 <code>rpc.js</code> 内独立处理，从 <code>authoring-guidance.js</code> 返回 id / hash / document 正文。</li>
        <li>不进入浏览器画布队列，也不调用模型；schema 校验同源（<code>schema.js</code>）。</li>
        <li><code>visual-explorer</code> 只列规则目录；<code>architecture</code> 为独立规则文件。</li>
      </ul>
    </div>
    <div class="panel pd"><h3><span class="tag">D</span>浏览器侧与虚拟源文件</h3>
      <ul>
        <li>画布文档与快照由浏览器持有，不是 Node 文件存储；Widget host 为沙箱 iframe。</li>
        <li>虚拟路径如 <code>objects/&lt;id&gt;/widget.html</code> 不是本机真实路径；<code>read_file</code> / <code>patch_file</code> 围绕同一文档的虚拟源工作。</li>
        <li>浏览器关闭授权后不再接受外部画布操作。内置 Agent（<code>document-tools.mjs</code>）复用共用操作，有独立绑定，<b>不是</b>外部 MCP 必经环节。</li>
      </ul>
    </div>
    <div class="panel pe"><h3><span class="tag">E</span>可选 Cloud 通道（边界已证实）</h3>
      <ul>
        <li>开启后浏览器经本地 <code>/api/mcp/cloud-canvas</code> 接入 <code>CloudMcpBridge</code>，带宿主设备凭据连接 Cloud WSS <code>/api/v1/mcp/device-canvas</code> 并双向转发画布帧。</li>
        <li>画布操作由 Cloud 的 MCP 运行时发起，<b>不</b>串过本地 HTTPS MCP 工具分派。</li>
        <li>云端内部实现未展开；<code>remote.js</code> 提供可复用的远端浏览器通道适配。</li>
      </ul>
