      <div class="panel">
        <h3><span class="tag" style="background:var(--teal)">A</span>传输与发现</h3>
        <ul>
          <li>主宿主由 <span class="mono">main.js</span> 创建 MCP service；MCP HTTPS 优先 3922 / 13922 / 23922，冲突后可选空闲端口——<b>同一 listener，不是多个服务</b>。</li>
          <li><span class="mono">discovery-client.js</span> / <span class="mono">lan-discovery.js</span>：已认证端点发现、共享缓存与 LAN 广播；先试已知地址与缓存，<b>无常驻发现守护进程</b>。</li>
          <li>本地主机与桥接端各有自己的信任 / 凭据资料；图中只画职责，不含凭据内容。</li>
        </ul>
      </div>
      <div class="panel">
        <h3><span class="tag" style="background:var(--purple)">B</span>会话 ID 与存储边界</h3>
        <ul>
          <li>四种 ID 互不相同：浏览器连接 ID、文档 ID、业务 sessionId、HTTPS 传输 session ID。</li>
          <li>绑定 <span class="mono">client/sessionKey → canvasId/documentId</span> 持久化在 Node 侧（<span class="mono">conversation-bindings.js</span>）。</li>
          <li>画布文档与快照<b>由浏览器持有</b>；虚拟路径如 <span class="mono">objects/&lt;id&gt;/widget.html</span> 不是模型电脑上的真实文件。</li>
        </ul>
      </div>
      <div class="panel">
        <h3><span class="tag" style="background:var(--orange)">C</span>工具调用生命周期（Widget 为例）</h3>
        <ul>
          <li>外部 AI 通过 <span class="mono">penecho_present_widget</span> 传入 HTML → 共用操作协调版本/hash、幂等 requestId、虚拟文件读写 → 浏览器执行文档动作。</li>
          <li>Widget 在浏览器沙箱 iframe 渲染；后续 <span class="mono">read_file</span> / <span class="mono">patch_file</span> 围绕<b>同一文档</b>的虚拟源文件工作。</li>
          <li>Node 端<b>不是 HTML 排版渲染器</b>；结果 / 错误 / 截图沿原请求通道返回。</li>
        </ul>
      </div>
      <div class="panel">
        <h3><span class="tag" style="background:var(--blue)">D</span>运维与旁路事实</h3>
        <ul>
          <li>HTTP 空闲清理<b>不终止</b>仍打开 stdin 的轻量桥；下次调用重连并恢复原文档，已提交的写请求不盲目重放。</li>
          <li>开启请求日志时 <span class="mono">request-trace.js</span> 记录多轮交互；日志目录与 Agent 日志平行，<b>不是画布源文件</b>。</li>
          <li>图片上传 <span class="mono">/mcp/images</span> 复用同一 HTTPS 接入与认证，服务端有界处理后交给指定文档。</li>
          <li>内置 Agent 的 <span class="mono">document-tools.mjs</span> 复用共用画布操作与 guidance，有独立会话绑定，<b>不是外部 MCP 的必经环节</b>。</li>
        </ul>
      </div>
    </div>

      <h3><span class="tag" style="background:var(--muted)">E</span>Cloud 可选通道（仅画已证实边界）</h3>
      <ul>
        <li>用户开启 Cloud MCP 后，浏览器经本地 <span class="mono">/api/mcp/cloud-canvas</span> 接入 <span class="mono">CloudMcpBridge</span>。</li>
        <li>桥带宿主设备凭据连接 Cloud 的 WSS <span class="mono">/api/v1/mcp/device-canvas</span>，<b>双向透明转发画布帧</b>。</li>
        <li>由 Cloud 的 MCP 运行时发起画布操作，<b>不表示云端请求必须串过本地 HTTPS MCP 工具分派</b>。</li>
        <li><span class="mono">remote.js</span> 另提供可复用远端浏览器通道适配；云端内部（数据库、队列、部署）未展开、不臆造。</li>
